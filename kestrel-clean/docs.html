Kestrel Documentation & Operations Manual

Deploy, tune, and operationalize Kestrel’s sovereign, zero-cloud monitoring daemon across personal micro-clusters, bare metal appliances, and rackmount infrastructure.

01

Getting Started

Prerequisites

Kestrel runs as a single static binary or micro-container tailored for minimal system footprint. It performs non-destructive passive sniffing, discrete multi-point synthetic probing, and automated topological neighbor discovery using local link protocols (LLDP / ARP / mDNS).

memory

Compute & Arch

Linux x86_64 or arm64. Optimized for Raspberry Pi 4/5, Intel NUC, and Proxmox VE hypervisors.

hard_drive

Memory Footprint

Requires less than 8 MB resident set size (RSS). Zero external runtime dependencies or JVM bloat.

lock_open

Rootless Execution

Designed to drop root immediately after binding synthetic socket raw capabilities.

verified_user Zero-Cloud Sovereign Guarantee

Kestrel initiates absolutely zero outbound telemetry pings to external public clouds, analytics servers, or telemetry aggregators. 100% of captured routing maps, switch states, and timeseries latency profiles remain stored locally in your local SQLite WAL volume.

02

Installation

Quick Deploy

The recommended production method for containerized homelab environments is Docker Compose or standalone Docker CLI with host networking enabled for accurate ARP scanning.

bash // docker deploy 
docker run -d \
  --name kestrel \
  --restart=unless-stopped \
  --net=host \
  --cap-add=NET_RAW \
  --cap-add=NET_ADMIN \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v ./kestrel.yaml:/etc/kestrel/kestrel.yaml \
  -p 8080:8080 \
  ghcr.io/kestrel-network/kestrel:latest
warning Linux Capabilities Notice

Both --cap-add=NET_RAW and --cap-add=NET_ADMIN are mandatory. They allow the containerized daemon to emit ICMP echo requests without running as root user inside the container namespace.

03

Configuration

YAML Spec

Kestrel reads declarative definitions from /etc/kestrel/kestrel.yaml. Hot reloads are triggered automatically upon file alteration using inotify filesystem watches.

Parameter Type Default Description
check_interval Duration 10s High-frequency ICMP and TCP ping polling frequency per subnet probe.
timeout Duration 1500ms Socket read timeout before flagging service latency warning or packet drop.
retention_days Integer 30 Local SQLite WAL time-series data retention window before auto-compaction.
notification_channels List<String> ["pushover", "discord"] Active notification egress targets for priority alert routing.
prom_exporter_port Integer 9090 Native Prometheus scrape endpoint for Grafana homelab dashboards.
kestrel.yaml sample YAML Specification 
# Core Telemetry Parameters
version: "1.4"
check_interval: 10s
timeout: 1500ms
retention_days: 30

# Active Probe Targets
subnets:
  - cidr: "192.168.1.0/24"
    label: "Homelab-LAN"
    scan_arp: true
  - cidr: "10.0.100.0/24"
    label: "IoT-Isolated-VLAN"
    scan_arp: false

# Metrics & Monitoring Export
prom_exporter_port: 9090
notification_channels:
  - "discord"
  - "gotify"

Frequently Asked Questions

Homelab Ops
Can I run Kestrel on an unprivileged Proxmox LXC? expand_more
Yes. Under unprivileged Proxmox LXC, simply append lxc.cap.keep: net_raw net_admin to your container configuration file in /etc/pve/lxc/{id}.conf. This grants synthetic raw ping capabilities without forfeiting unprivileged user namespace separation.
How much disk write activity occurs on flash storage? expand_more
Kestrel batches timeseries points in memory and executes synchronized disk flushes once every 60 seconds into a Write-Ahead Log (WAL). An average 64-node homelab generates under 12 MB of total flash writes every 24 hours, preventing wear on consumer SSDs and high-end microSD cards.
Can Kestrel monitor VLANs across managed switches? expand_more
Yes. With 802.1Q tagged sub-interfaces attached to the host (e.g. eth0.10, eth0.20) or an internal bridge, Kestrel inspects isolated subnets concurrently without routing between them, keeping sensitive management and IoT zones completely segmented.
